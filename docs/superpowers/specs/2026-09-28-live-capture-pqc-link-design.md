# 实时抓包与后量子检测联动设计

## 目标

协议分析支持现场抓包并复用文件分析；对抓包中的每条 TLS 会话分别展示被动观察和另一次主动探测的证据。页面调整为主界面第二页。

## 流程

1. 用户选择网卡、BPF 过滤条件、最长抓包时间和保存路径，开始或手动停止。后台抓包结束后保存 pcap，再走现有文件分析流程。抓包权限、无数据包与 BPF 错误在界面显示。
2. 列出包含 TLS 握手的会话。选中会话后，从该会话的 ClientHello 读取 SNI，从正式 ServerHello 的 key_share 读取组选项与长度；缺少任一证据就标为无法判断。TLS 1.3 的加密证书在未解密的 pcap 中标为无法观察。
3. 用户对选中会话执行主动复测。目标优先采用抓包 SNI，缺失时采用服务器 IP，并沿用抓包目标端口；后台调用现有深度检测。界面并列呈现两份证据，并注明主动检测是另一条连接。

## 边界

- 被动抓包不推断服务器未提供的算法支持，也不把后量子组 ID 当作完成密码学校验。
- 主动结果不覆盖抓包结果；两次连接的证书与协商结果不合并成同一连接结论。
- 不自动探测抓包中出现的外部主机；仅在用户点击主动复测后联网。
- TLS 1.3 pcap 密钥日志解密不在本次范围，界面清晰标注证书层不可见。

## 验证

使用构造的 TLS 握手测试被动组识别、缺失与错误长度；测试抓包停止及保存边界；Qt 离屏测试页签顺序、会话选择与双证据展示；运行现有测试套件。
