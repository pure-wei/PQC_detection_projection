# 本地后量子实验站多协议与签名设计

用户已选择 TLS/HTTPS＋TCP/UDP 应用消息实验。实验站保留在第二个主页签。

## 范围与交互

- HTTPS：完整 TLS 1.3、指定实验 CA 验证、真实 GET 与页面字节比较。
- TLS：完成真实 TLS 1.3 握手，验证证书与签名，不将其标为 HTTPS 请求成功。
- TCP / UDP：本机自定义签名消息协议；服务器签署客户端随机挑战及消息，客户端以本地固定公钥验签。明确显示明文传输，无 TLS 和证书链。
- TLS 的密钥交换支持 X25519MLKEM768、SecP256r1MLKEM768、SecP384r1MLKEM1024；证书与握手签名支持 ML-DSA-44/65/87。
- 消息签名复用项目的 17 种后量子算法：3 种 ML-DSA、12 种 SLH-DSA、2 种 Falcon。可组合 Ed25519、ECDSA-P256/P384、RSA-PSS-2048/3072，接受规则为两份签名全部有效。
- 页面可选协议、密钥交换、签名与混合签名参数，输入消息；启动、重测、停止与关闭行为沿用现有进程管理。

## 后端与证据

- profiles.py 统一配置与验证。所有报告和运行记录包含实际 profile，不能把旧模式的结果当作新模式的成功。
- TLS 身份按签名算法分别保存，保留已有默认 ML-DSA-65 身份；私钥不进入公开目录。
- signed_messages.py 管理临时签名身份、固定公钥校验、网络服务与负向检查。私钥仅留在服务进程内存。
- TCP 使用四字节长度帧；UDP 使用带挑战标识的应用分片，每片最多 1200 字节，总响应上限 128 KiB，拒绝冲突、越界及不完整分片。
- 消息最长 4096 UTF-8 字节；通信、并发与停止均有边界。所有服务只监听 127.0.0.1。
- 后端成功必须来自真实通信与验签；篡改消息、签名、公钥、协议及挑战均不得成功。混合模式必须分别验证两个组成部分。
- 报告区分握手、HTTPS、明文消息签名和信任范围；网页仅展示报告，不因 HTTP 访问声称浏览器具有 PQC 连接。
- 默认模式与原有 CLI/API 保持兼容，原有 11 项 HTTPS 实验检查保留。

## 验收

实际跑通全部 9 种 TLS 密钥交换与签名组合，全部 17 种签名在 TCP 与 UDP 上完成传输及负向检查。补测 5 种经典混合签名、UDP 最大签名分片、配置边界、不同模式的真实 GUI 生命周期和网页报告真实性。完整项目回归必须通过。
