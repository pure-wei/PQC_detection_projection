EXPLICIT TRUST

TLS 使用显式指定的实验 CA；TCP/UDP 使用本地固定签名公钥。以本次实测报告为准。

TCP/UDP 签名消息属于本机应用协议，提供签名验证，不加密消息内容。TLS 的握手签名与应用消息签名分别验证。

实验 CA 不等同于公共受信 CA。HTTP 展示入口本身不提供 PQC TLS；浏览器当前连接与报告中的被测连接分别判断。

ACCESS & TRUST

访问说明与常见问题

查看报告用哪个入口？

默认 HTTP 展示入口是 http://127.0.0.1:8080/index.html，查看报告无需导入证书。自定义 HTTP 端口时，请使用启动命令输出的地址；被测 TLS 端点以实测报告为准。

为什么 HTTPS 打不开？

被测 TLS 端口提供 HTTPS，地址栏需输入完整的 https://localhost:8443/index.html，不能在该端口使用 HTTP。

浏览器尚未信任私有实验 CA 时，会显示 ERR_CERT_AUTHORITY_INVALID。这是证书信任错误，不代表端点没有启用 TLS。

即使信任实验 CA，浏览器也仍需支持服务端使用的 TLS 算法。是否通过本实验，以验证命令生成的真实报告为准。

如何主动管理实验 CA 信任？

仅在你核对实验根证书并主动选择信任后，才自行运行导入命令。以下命令均在项目根目录执行；本页面不会自动导入证书，也不会替你执行命令。

先查看证书及信任状态
powershell -File pqc_lab/trust-root.ps1 -Action inspect
选择信任此实验 CA 时，手动导入
powershell -File pqc_lab/trust-root.ps1 -Action install
实验结束后，可手动移除信任
powershell -File pqc_lab/trust-root.ps1 -Action remove
